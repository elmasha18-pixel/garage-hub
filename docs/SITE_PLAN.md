# План сайта GarageHub

Подготовлено 21.10.2026. Сайт делаем, когда в каталоге будет 5–10 настоящих гаражей (решение Эльмана).

## Зачем сайт
1. **Клиенты из Яндекса.** Люди ищут «аренда гаража по часам Марьино», бот поисковики не видят.
2. **Работа без Telegram и VPN.** Часть аудитории до Telegram не доходит.
3. **Удобная админка.** Добавлять объекты с фото с компьютера, а не по одному полю в боте.
4. **Владельцы сами заводят свой бокс** (вы только одобряете).

## Что уже готово (фундамент)
| Часть | Где | Что даёт сайту |
|---|---|---|
| Бизнес-правила брони | `core/service.py` | Бот, Mini App и сайт бронируют по одним правилам |
| Работа с базой | `core/db.py` | Все запросы в одном месте |
| HTTP API | `api/` | Сайт использует тот же API, что Mini App |
| Открытый каталог | `GET /api/garages`, `/api/garages/{id}`, `/availability` | Без входа, только публичные поля |
| Интерфейс | `webapp/` (без сборки) | Экраны каталога, карточки, брони переиспользуются |
| Дизайн-система | `webapp/DESIGN.md`, `webapp/css/` | Сайт в том же стиле, без шаблонности |
| Тесты | `tests/run_all.py` | Любая правка проверяется одной командой |

## Как будет устроено
Один сервер, один процесс: бот + API + сайт (как сейчас бот + Mini App).

- **Публичные страницы — готовым HTML с сервера**, чтобы Яндекс видел текст сразу:
  - `/` — главная: короткое объяснение, районы, свежие боксы;
  - `/garage/<id>-<slug>` — страница бокса (фото, цена, характеристики, кнопка брони);
  - `/district/<slug>` — боксы района;
  - `sitemap.xml`, `robots.txt`, разметка schema.org (адрес, цена) для красивых сниппетов.
- **Бронирование и «Мои заявки»** — те же экраны из `webapp/`, после входа.
- **Вход на сайте** — кнопка «Войти через Telegram» (Telegram Login Widget). Тот же аккаунт, что в боте: заявки общие. Для домена нужна команда `/setdomain` в @BotFather.
- **Админка** — раздел «Управление» из Mini App + добавление и редактирование объектов с загрузкой фото.

## Что нужно сделать в коде (по порядку)
1. **Фото: уйти от Telegram file_id.** Сайту нужны обычные ссылки на картинки и загрузка с компьютера. Хранилище — диск сервера или Yandex Object Storage; перенос старых фото — через уже работающий кеш `cache/photos`.
2. **Адреса страниц:** поле `slug` у объекта (`sql/002_site.sql`, написать при старте работ).
3. **Серверные страницы** (шаблоны с автоэкранированием) + `sitemap.xml`, `robots.txt`, schema.org.
4. **Гостевой режим `webapp/`:** каталог и карточка открываются без входа, вход — только при брони.
5. **Вход через Telegram Login Widget** + сессия (cookie) на сервере, проверка подписи как у Mini App.
6. **Админка на сайте:** добавить/изменить объект, загрузить фото, архив.
7. **Заявка владельца на сайте** с анкетой объекта — объект создаётся «на проверке».
8. **Юридическое:** политика обработки персональных данных, согласие в формах, реквизиты (ИП).

## Что нужно решить Эльману
- **Домен.** Например, garagehub.ru или гаражчас.рф — проверить, свободен ли.
- **Сервер в России** (Timeweb или аналог), примерно 300–600 ₽ в месяц. Туда же переедет бот — работать 24/7 без Мака и без временного туннеля.
- **Данные в России.** По 152-ФЗ персональные данные россиян хранятся в РФ. Supabase за рубежом — при запуске сайта переносим базу на российский сервер (Postgres).
- **Когда стартуем** — ориентир: 5–10 реальных гаражей в каталоге.

## Чего не делаем
- Отдельное мобильное приложение — Mini App и сайт его заменяют.
- Сложный фреймворк со сборкой — текущий подход без сборки проще поддерживать.
