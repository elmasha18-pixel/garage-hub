# GarageHub — контекст проекта

Этот файл читается автоматически в начале каждой сессии. Здесь всё, что нужно знать о проекте, чтобы продолжить работу без пересказа.

## Что это

GarageHub — Telegram-бот (@garazh_rent_bot) для почасовой аренды **гаражей самообслуживания** и **детейлинг-боксов** в Москве и Московской области. Человек находит бокс, выбирает дату и часы, оставляет заявку, приезжает и сам чинит или моет машину.

Владелец проекта — Эльман (Telegram @mamedov99999, ID 5121580545). Он не программист: объясняй простым языком, давай команды для Терминала целиком и по одной, не рассчитывай на знание Linux.

## Бизнес-модель и стадия

- Сейчас стадия **набора базы**: комиссии нет, размещение для владельцев бесплатное. Цель — 20–30 объектов в Москве и области, потом рост.
- Позже: комиссия 10–15% с брони через эквайринг (ЮKassa или Т-Касса), агентская схема (ИП на УСН, агентский договор с владельцами, оферта для клиентов).
- Оплата сейчас **на месте, напрямую площадке**. Бот деньги не принимает.
- Первые 20–30 предложений владельцам (с Авито) уже отправлены, ждём ответов.

## Ключевой принцип: админ — диспетчер

На старте **все заявки клиентов идут только админу (Эльману)**, не владельцу гаража:

1. Клиент оставляет заявку и получает «заявка отправлена, ожидайте подтверждения».
2. Админу приходит уведомление: клиент, объект, дата и время, сумма + **скрытые контакты владельца** (имя, телефон, Telegram).
3. Админ сам звонит владельцу и согласует.
4. Админ жмёт «Подтвердить» → клиенту приходит «подтверждено, можно приезжать» с адресом. Или «Отказать» → бот просит причину → клиенту приходит отказ с причиной.

Позже владельцы будут подтверждать сами, поэтому архитектуру под это не ломать.

**Важно для текстов:** клиенту и владельцу **нигде не писать**, что «мы сами свяжемся с владельцем», «сами договоримся», «согласуем за вас». Это внутренняя кухня.

## Роли

- **Админ** (ADMIN_ID): добавляет объекты (только он), смотрит все объекты, редактирует любое поле по одному, видит «Новые заявки» (pending, по времени начала) и «Заявки сегодня» (pending + confirmed на сегодня, от раннего к позднему), подтверждает и отклоняет.
- **Клиент**: «Найти бокс» (фильтры), карточка, бронирование, «Мои заявки» (история со статусами и причиной отказа).
- **Владелец**: кнопка «Разместить бокс» — оставляет заявку (имя, телефон, тип, адрес). Она приходит админу сообщением, в БД пока не пишется. Объекты владельцев добавляет админ.

## Объект (таблица `garages`)

Поля: `type` (`garage` | `detailing`), `name`, `district` (свободный текст), `address`, `photos` (TEXT[] — Telegram file_id, до 5), `price_per_hour`, `has_lift`, `has_pit`, `tool_availability` (`all` | `none` | `partial`), `box_size` (`small` до 4,5 м | `medium` до 5,5 м | `large` до 7 м), `working_hours` (текст), `description`, `owner_name`, `owner_phone`, `owner_contact`. Последние три — **только для админа, клиенту не показывать**. `owner_telegram_id` сейчас равен ADMIN_ID.

Фото хранятся как Telegram `file_id`, Supabase Storage не используется.

## Поиск (клиент)

Пошаговые фильтры, каждый можно пропустить: тип → район → подъёмник → яма → инструмент.

- **Районы** не захардкожены: список берётся из уже добавленных объектов (distinct `district`), по алфавиту, с **мультивыбором** (отметка ✓, сообщение редактируется на месте).
- **Геолокацию не использовать**: в Москве Telegram работает через VPN, геолокация ненадёжна. Это осознанное решение.
- Список → краткая карточка с 1 фото и «Подробнее» → полная карточка (альбом до 5 фото) и «Забронировать».

## Бронирование (таблица `bookings`)

Поля: `garage_id`, `client_telegram_id`, `client_username`, `start_time`, `end_time` (timestamptz), `total_price`, `status` (`pending` | `confirmed` | `rejected` | `cancelled`), `admin_comment` (причина отказа).

- Даты: 7 дней вперёд. Слоты по часу, 09:00–22:00 (пока общие, не из `working_hours`).
- Часы только подряд. Занятые (pending + confirmed) и прошедшие недоступны. Перед записью повторная проверка занятости.
- Сообщения со слотами редактируются на месте (edit_text), а не плодятся.

## Стек и файлы

- Python **3.9.6** (системный на маке). **Не использовать синтаксис 3.10+**: `match`, `X | None` в аннотациях и т.п.
- aiogram 3, supabase-py 2, python-dotenv. Зависимости в `requirements.txt`, окружение в `venv/`.
- БД — Supabase (Postgres). Схему меняем SQL-запросами в Supabase → SQL Editor. Эльман выполняет их сам, давай ему готовый SQL с `ADD COLUMN IF NOT EXISTS`.
- Parse mode — HTML. Пользовательский текст экранировать (`html.escape`).

Файлы:
- `bot.py` — хендлеры, FSM-состояния, логика.
- `config.py` — загрузка `.env`, клиент Supabase, константы (ADMIN_ID, часы работы, MAX_PHOTOS и т.д.).
- `keyboards.py` — все клавиатуры и класс `Btn` с текстами кнопок меню.
- `texts.py` — **все тексты бота** и функции форматирования карточек. Тексты правим здесь, а не в bot.py.
- `.env` — `TELEGRAM_BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (+ опционально ADMIN_*). **Никогда не выводить содержимое в чат.**

Запуск:
```bash
cd ~/Desktop/garage_bot && source venv/bin/activate && python3 bot.py
```
Если venv сломался (например, после переноса папки): `rm -rf venv && python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt`.

Ошибки `TelegramNetworkError: Server disconnected` при старте — обычно сеть или VPN, бот переподключается сам.

## Грабли, на которые уже наступали

- **Конфликт callback_data между добавлением и редактированием.** Одинаковые callback (`tools_*`, `size_*`) ловились хендлерами добавления, и редактирование одного поля запускало весь сценарий добавления. Решение — **отдельные префиксы для редактирования** (`etools_*`, `esize_*`, `editval_*`). Любое новое поле редактирования делать со своим префиксом.
- Редактирование должно менять **ровно одно поле**, сохранять и возвращать в админ-меню.
- Порядок регистрации хендлеров важен: более общий `startswith` может перехватить более конкретный.
- Кнопка в меню и её хендлер должны существовать парой (раньше были кнопки без хендлеров).

## Стиль текстов и интерфейса

- Тон спокойный, вежливый, брендированный, без «нейросетевой» восторженности. Обращение на «вы».
- Оформление: жирный заголовок, разделитель `──────────────`, строки «Поле: значение». Эмодзи минимально, не в каждой строке.
- Терминология: «гараж самообслуживания», «детейлинг-бокс», «бокс». В текстах для владельцев — «сервис почасовой аренды гаражей», без слова «бот» и без «площадки, которую ищут клиенты».
