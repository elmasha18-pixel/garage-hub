# GarageHub — контекст проекта

Этот файл читается автоматически в начале каждой сессии. Здесь всё, что нужно знать о проекте, чтобы продолжить работу без пересказа.

## Что это

GarageHub — Telegram-бот (@garazh_rent_bot) для почасовой аренды **гаражей самообслуживания** и **детейлинг-боксов** в Москве и Московской области. Человек находит бокс, выбирает дату и часы, оставляет заявку, приезжает и сам чинит или моет машину.

Владелец проекта — Эльман (Telegram @mamedov99999, ID 5121580545). Он не программист: объясняй простым языком, давай команды для Терминала целиком и по одной, не рассчитывай на знание Linux.

## Бизнес-модель и стадия

- Сейчас стадия **набора базы**: комиссии нет, размещение для владельцев бесплатное. Цель — 20–30 объектов в Москве и области, потом рост.
- Позже: комиссия 10–15% с брони через эквайринг (ЮKassa или Т-Касса), агентская схема (ИП на УСН, агентский договор с владельцами, оферта для клиентов).
- Оплата сейчас **на месте, напрямую площадке**. Бот деньги не принимает.
- Первые 20–30 предложений владельцам (с Авито) уже отправлены, ждём ответов.

## Ключевой принцип: админ — диспетчер

На старте **все заявки клиентов идут только админу (Эльману)**, не владельцу гаража:

1. Клиент оставляет заявку и получает «заявка отправлена, ожидайте подтверждения».
2. Админу приходит уведомление: клиент, объект, дата и время, сумма + **скрытые контакты владельца** (имя, телефон, Telegram).
3. Админ сам звонит владельцу и согласует.
4. Админ жмёт «Подтвердить» → клиенту приходит «подтверждено, можно приезжать» с адресом. Или «Отказать» → бот просит причину → клиенту приходит отказ с причиной.

Позже владельцы будут подтверждать сами, поэтому архитектуру под это не ломать.

**Важно для текстов:** клиенту и владельцу **нигде не писать**, что «мы сами свяжемся с владельцем», «сами договоримся», «согласуем за вас». Это внутренняя кухня.

## Роли

- **Админ** (ADMIN_ID): добавляет объекты (только он), смотрит все объекты, редактирует любое поле по одному, видит «Новые заявки» (pending, по времени начала) и «Заявки сегодня» (расписание дня, листается на 7 дней вперёд), подтверждает и отклоняет (готовые причины или своя), удаляет объекты в архив и возвращает, видит «Заявки владельцев» и «Панель» со счётчиками.
- **Клиент**: «Найти бокс» (фильтры), карусель карточек, бронирование, «Мои заявки» (предстоящие и история, отмена брони — админ получает уведомление).
- **Владелец**: кнопка «Разместить бокс» — оставляет заявку (имя, телефон, тип, адрес). Пишется в `owner_requests` (status `new` → `done`) и приходит админу с кнопкой «Обработано». Объекты владельцев добавляет админ.

## Объект (таблица `garages`)

Поля: `type` (`garage` | `detailing`), `name`, `district` (свободный текст), `address`, `photos` (TEXT[] — Telegram file_id, до 5), `price_per_hour`, `has_lift`, `has_pit`, `tool_availability` (`all` | `none` | `partial`), `box_size` (`small` до 4,5 м | `medium` до 5,5 м | `large` до 7 м), `working_hours` (текст), `description`, `owner_name`, `owner_phone`, `owner_contact`, `is_active` (false = архив), `open_hour`/`close_hour` (слоты брони, вычисляются из `working_hours`). Три поля owner_* — **только для админа, клиенту не показывать**. `owner_telegram_id` сейчас равен ADMIN_ID.

Фото хранятся как Telegram `file_id`, Supabase Storage не используется.

## Поиск (клиент)

Пошаговые фильтры, каждый можно пропустить: тип → район → подъёмник → яма → инструмент.

- **Районы** не захардкожены: список берётся из уже добавленных объектов (distinct `district`), по алфавиту, с **мультивыбором** (отметка ✓, сообщение редактируется на месте).
- **Геолокацию не использовать**: в Москве Telegram работает через VPN, геолокация ненадёжна. Это осознанное решение.
- Результаты — карусель: одно сообщение с фото и полной карточкой, ◀ N/M ▶, «Все фото», «На карте ↗» (Яндекс.Карты по адресу), «Забронировать». Объект без фото показывается с заглушкой `assets/placeholder.png`. Для детейлинга шаги подъёмник/яма/инструмент пропускаются.

## Бронирование (таблица `bookings`)

Поля: `garage_id`, `client_telegram_id`, `client_username`, `start_time`, `end_time` (timestamptz), `total_price`, `status` (`pending` | `confirmed` | `rejected` | `cancelled`), `admin_comment` (причина отказа), `created_at`, флаги напоминаний `admin_reminded`, `client_wait_notified`, `visit_reminded`.

- Даты: 7 дней вперёд, на кнопке — число свободных часов. Слоты по часу из `open_hour`–`close_hour` объекта (по умолчанию 09–22).
- Часы только подряд: нажал начало и конец — диапазон выбрался сам, сумма считается на лету. Занятые (pending + confirmed) и прошедшие недоступны. Перед записью повторная проверка занятости.
- Сообщения со слотами редактируются на месте (edit_text), а не плодятся.

## Стек и файлы

- Python **3.9.6** (системный на маке). **Не использовать синтаксис 3.10+**: `match`, `X | None` в аннотациях и т.п.
- aiogram 3, supabase-py 2, python-dotenv. Зависимости в `requirements.txt`, окружение в `venv/`.
- БД — Supabase (Postgres). Схему меняем SQL-запросами в Supabase → SQL Editor. Эльман выполняет их сам, давай ему готовый SQL с `ADD COLUMN IF NOT EXISTS`.
- Parse mode — HTML. Пользовательский текст экранировать (`html.escape`).

Файлы (v2, с 15.10.2026):
- `bot.py` — точка входа: логи (`logs/bot.log`), порядок роутеров, обработчик ошибок (шлёт админу ⚠ не чаще раза в минуту), команды меню, запуск напоминаний. При старте проверяет схему БД и не запускается, если SQL не выполнен.
- `handlers/common.py` — /start (клиенту обложка `assets/cover.png`, админу панель со счётчиками), **все кнопки нижнего меню**, /client и /admin. Подключается первым, поэтому меню работает в любом состоянии.
- `handlers/search.py` — поиск: мастер фильтров в одном сообщении (шкала шагов, живой счётчик «Подходит: N»), результаты каруселью ◀ 1/5 ▶ (одно фото-сообщение, листается edit_media).
- `handlers/booking.py` — бронь (даты с числом свободных часов → сетка часов, выбор диапазона двумя нажатиями, живая сумма) и «Мои заявки» с отменой.
- `handlers/owners.py` — заявка владельца (4 шага, кнопка «Отправить мой номер»), пишется в `owner_requests`.
- `handlers/admin_objects.py` — каталог, архив, карточка объекта, добавление (шкала прогресса, предпросмотр перед публикацией), редактирование по одному полю, фото (добавить/заменить), удаление = перенос в архив.
- `handlers/admin_bookings.py` — новые заявки, расписание по дням (◀ сегодня ▶), подтверждение, отказ с готовыми причинами, заявки владельцев.
- `reminders.py` — фоновый цикл раз в минуту: админу про заявку без ответа (15 мин), клиенту «ещё на согласовании» (60 мин), клиенту «скоро визит» (за 2 ч). Флаги в `bookings`.
- `db.py` — **все запросы к Supabase** (хендлеры в базу напрямую не ходят). Смена статуса заявки — только через `change_booking_status` с `allowed_from`: повторное нажатие старой кнопки ничего не ломает.
- `callbacks.py` — данные inline-кнопок (aiogram `CallbackData`), у каждого сценария свой префикс.
- `keyboards.py` — все клавиатуры и `Btn` с текстами кнопок меню.
- `texts.py` — **все тексты** и оформление карточек. Тексты правим здесь.
- `states.py` — FSM-состояния. `utils.py` — роли, время, часы работы, блокировки, `reset(state)`.
- `media.py` — фирменные картинки (`assets/*.png`, исходники `*.svg`), кеш file_id.
- `sql/` — миграции. `001_v2.sql`: `garages.is_active/open_hour/close_hour`, флаги напоминаний в `bookings`, таблица `owner_requests`.
- `.env` — `TELEGRAM_BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (+ опционально ADMIN_*). **Никогда не выводить содержимое в чат.** В git не попадает (`.gitignore`).

**Mini App (с 21.10.2026)** — веб-приложение с тем же функционалом (поиск, бронь, мои заявки, заявка владельца, контакты + раздел «Админ»: заявки, расписание, объекты в архив/из архива, заявки владельцев). Оно же — задел под сайт.
- `webapp/` — фронтенд **без сборки** (чистый JS-модули + CSS, Node не нужен). `index.html`, `css/` (tokens — цвета/темы, base, components), `js/` (`router.js` hash-роутер, `store.js`, `api.js`, `tg.js` обёртка над Telegram, `format.js`, `dom.js` — шаблоны с автоэкранированием, `screens/*` — экраны, `ui/*` — компоненты).
- `api/` — aiohttp: `auth.py` (проверка подписи Telegram initData), `routes.py`, `serializers.py` (**контакты владельца только в admin_*-функциях**), `photos.py` (прокси фото Telegram file_id → кеш `cache/photos`), `server.py`. Запускается в одном процессе с ботом (порт WEB_PORT, по умолчанию 8080, слушает только 127.0.0.1).
- `service.py` — **общая бизнес-логика бота и Mini App** (создание заявки, подтверждение, отказ, отмена). Правила менять только там.
- Вход: заголовок `Authorization: tma <initData>`. Для разработки без Telegram: `MINIAPP_DEV=1` и `?dev=client|admin` — работает только с localhost и без прокси-заголовков. **На сервере MINIAPP_DEV не включать.**
- Админ-раздел в Mini App пока **не умеет** добавлять/редактировать объекты и фото (это в боте): фото лежат как Telegram file_id, нужен переход на нормальное хранилище.
- Telegram открывает Mini App только по **публичному HTTPS**. Сейчас — временный туннель (`start.sh`, см. «Запуск»). На сервере — постоянный домен: прописать `WEBAPP_URL` в `.env`, туннель не нужен.
- Разработка интерфейса без бота: `python3 dev_web.py` → http://localhost:8080/?dev=client (или `?dev=admin`). Этот режим **ничего не отправляет** в Telegram (QuietBot). Демо-объекты: `tests/demo_data.py`, уборка: `tests/cleanup.py`.
- Тесты: `tests/t_api.py` (49+ проверок API, прав, безопасности), `tests/t_all.py` (бот).

Проект в git (локально). Перед крупными правками — коммит, чтобы можно было откатиться.

Админ может посмотреть бота глазами клиента: `/client`, вернуться — `/admin`.

Запуск (с 21.10.2026) — **одной командой**, бот + временный HTTPS для Mini App, Мак не засыпает:
```bash
cd ~/Desktop/garage_bot && ./start.sh
```
Остановить: Ctrl+C. Только бот без приложения: `source venv/bin/activate && python3 bot.py`.

Как устроен временный HTTPS (пока нет сервера):
- `tunnel.py` держит SSH-туннель к **localhost.run** (без регистрации) → адрес вида `https://xxxx.lhr.life`, пишет его в `cache/webapp_url.txt`, при обрыве переподключается (адрес при этом меняется).
- Бот раз в 30 с читает файл (`config.webapp_url()`) и сам обновляет кнопку «Открыть» (MenuButtonWebApp). Нет адреса — кнопка убирается. `/app` всегда даёт актуальную кнопку.
- **Cloudflare Tunnel в этой сети не работает**: системный DNS нестандартный (Go-программы видят пустой /etc/resolv.conf), QUIC режется, TLS к edge обрывается. Не тратить время.
- Telegram `getChatMenuButton` отдаёт закешированное значение несколько минут после смены — это не ошибка установки.
- Наружу торчит только веб-сервер бота (127.0.0.1:8080): API требует подписи Telegram, dev-вход через туннель запрещён, `.env` недоступен (есть тесты).

Если venv сломался (например, после переноса папки): `rm -rf venv && python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt`.

Ошибки `TelegramNetworkError: Server disconnected` при старте — обычно сеть или VPN, бот переподключается сам.

## Грабли, на которые уже наступали

- **Конфликт callback_data между сценариями.** Раньше одинаковые callback (`tools_*`) ловились и добавлением, и редактированием. Теперь у каждого сценария свой класс `CallbackData` с уникальным префиксом в `callbacks.py` (`AddCb`, `EditValCb` и т.д.). Новый сценарий = новый класс.
- Редактирование меняет **ровно одно поле**, сохраняет и показывает обновлённую карточку объекта.
- Порядок роутеров важен: `common` (меню) первым, иначе текст кнопки меню попадёт в поле ввода сценария.
- Кнопка в меню и её хендлер должны существовать парой.
- `state.clear()` не использовать напрямую — только `utils.reset(state)`: он сохраняет результаты поиска, чтобы карусель листалась после захода в другое меню.
- Альбом фото приходит пачкой одновременных сообщений — обработку фото и отправку брони держать под `user_lock`, иначе данные затираются.
- Колонки `open_hour/close_hour` NOT NULL: если часы не распознаны, писать значения по умолчанию 9–22, а не NULL.
- Запросы к Supabase идут из разных потоков — **HTTP/2 для клиента выключен** (config.py), иначе под нагрузкой случайные `ReadError`.
- Блокировка `user_lock` не реентерабельна: если обработчик уже держит её, а `service` берёт снова — зависание. Блокировку берёт только service.
- В Mini App всё, что приходит из базы, вставляется через `html\`...\`` (автоэкранирование). Не собирать HTML конкатенацией строк.
- Объекты не удаляются физически, только `is_active=false` (архив): иначе ломается история заявок.
